# Plan

The backlog for QuakeC Studio, kept as data so nothing in the [design document](../docs/design/design-doc.md) is missed.

| File | Purpose |
| --- | --- |
| `requirements.yaml` | Every requirement in the design document with an ID; `implied` ones are needed to deliver a stated requirement but were not written down |
| `backlog/_meta.yaml` | Milestones (phases and their gates), labels, sizes and the definition of done |
| `backlog/p*.yaml` | Issues per phase: deliverable, acceptance criteria, verification, requirements, dependencies |
| `backlog/readiness.yaml` | One test-suite readiness review per layer per phase (generated by `gen_readiness.py`) |
| `check.py` | Fails if a requirement is uncovered, an issue is incomplete or cites an unknown requirement, dependencies cycle or skip a phase, a gate is incomplete, a decision names no ADR, a decision is not labelled `needs:human`, the design doc changed since `requirements.yaml` was reviewed against it, or `coverage.md` is stale; `--write-coverage` rewrites `coverage.md`. `cargo xtask ci` runs it and its tests |
| `test_check.py` | Negative tests: each rule must catch a deliberate fault |
| `apply.py` | Creates or updates labels, milestones and issues on GitHub, idempotently |
| `status.py` | A phase's progress from the plan and GitHub, by track (`build`, `review`, `human`, `agents`); its last line is the verdict `/goal` tests |
| `test_status.py` | Tests for `status.py` |
| `review_page.py` | Renders the plan as one HTML review page |

## Rules the checker enforces

- Phases run in order: every issue depends on the previous phase's gate; post-MVP (`LATER`) issues wait for the MVP gate.
- Layers wait for tested foundations: an issue that builds on a lower layer depends on that layer's readiness review (`docs/testing.md`).
- People: every decision is labelled `needs:human`, so agents prepare it but never close it. Gates are closed by the reviewer agent once every issue in the phase is closed and nothing was deferred; the MVP gate, which publishes the release, stays `needs:human`. An agent that stops for a person adds the `escalated` label, which `apply.py` never removes.

## When the design doc changes

`requirements.yaml` records `design_doc_sha256`, the SHA-256 of `docs/design/design-doc.md` it was last reviewed against. A PR that changes the design doc fails `check.py` until the requirements are reviewed against the change and the new hash, which the failure prints, is recorded. The PR template asks for this.

## Commands

```bash
python3 plan/check.py --write-coverage     # validate and refresh coverage.md
python3 -m unittest discover -s plan -p 'test_*.py'  # checker and status tests
python3 plan/gen_readiness.py              # after adding or relabelling feature/test issues
python3 plan/apply.py --repo quakecstudio/editor --dry-run
python3 plan/status.py --phase P0                 # what is closed, ready and waiting
python3 plan/review_page.py out.html
```
