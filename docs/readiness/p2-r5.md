## 5. Independent review (TEST-9)

- **Reviewer and time spent:** a Claude agent session, one working session on 2026-10-29,
  spent mostly on `qs-settings`' in-place editing, the code #608 added.
- **Tests added** (6, all kept):
  - `crates/qs-settings/src/tests.rs`:
    - `a_byte_order_mark_is_read_and_kept`
    - `a_mixed_line_ending_file_is_written_with_crlf`
    - `a_quoted_table_name_is_edited_in_place`
    - `control_characters_in_a_filter_read_back_from_the_file` (tab, DEL, C1 controls and
      U+2028)
    - `the_first_project_setting_makes_its_directory`
  - `crates/qs-commands/src/tests.rs`:
    - `a_session_runs_on_another_thread_and_a_registry_is_shared`: the session executes,
      undoes and redoes on another thread, and four threads read one registry at once. It
      checks P2-147's fix at run time; #608's test checks it only when the tests compile.
- **Defects found:**
  - **A settings edit dropped a UTF-8 byte order mark.** `toml_edit` reads past the mark and
    does not write it back, so any `settings.set` or `settings.reset` changed the file's
    first bytes, against the README's "the rest of the text stays as it was". Fixed in
    `edit` (`crates/qs-settings/src/lib.rs`): the mark is taken off before parsing and put
    back on the written text. `a_byte_order_mark_is_read_and_kept` failed before the fix and
    passes with it.
  - **Mixed line endings were rewritten.** In a file that mixes CRLF and LF lines, an edit
    writes every line with CRLF, including lines it does not touch; the README only promised
    that a CRLF file keeps its endings. Keeping each line's own ending would need a
    line-by-line merge of `toml_edit`'s output, which always uses `\n`. The behaviour is kept
    and stated in the README ("Hand edits and commands"), and
    `a_mixed_line_ending_file_is_written_with_crlf` pins it.
  - **Dead code** (section 2): `is_default` and `skip_serializing_if` were left behind when
    #608 removed `SettingsFile::save`. They are removed.

  By the owner's rule (2026-10-27) a readiness gap is fixed in the readiness pull request
  rather than filed as a follow-up, so these fixes are in this review's pull request.
- **First review's defects:** P2-147 (#620), a session not `Send`, and P2-148 (#621),
  settings writes overwriting hand edits and stripping comments, are fixed in #608 with their
  regression tests and are closed.

Also noted, not defects (unchanged from the first review): each `Setting`'s schema describes
the key only by its name, not its summary; and `settings.set`'s `value` has an unconstrained
schema, its type being checked only when the command runs.
