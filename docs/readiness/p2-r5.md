## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Claude agent session, one working session on 2026-10-29.
- **Tests added** (17, all kept):
  - `crates/qs-commands/src/tests.rs`: `a_panicking_params_deserialiser_is_caught`,
    `a_panicking_output_serialiser_is_caught_and_clears_the_history`,
    `a_builtin_refuses_arguments_that_are_not_an_object`,
    `undo_and_redo_by_id_name_the_command_and_refuse_an_empty_history`, `lookup_is_exact`,
    `ids_just_past_the_limits_are_rejected` (one byte over 128, and a multi-byte character
    that fits by characters but not bytes), `a_command_named_commands_links_past_the_title`,
    and the property `the_history_matches_a_two_stack_model`, which fails when the session
    stops emptying the redo history on a new change (checked by removing that line).
  - `crates/qs-settings/src/tests.rs`: `settings_set_refuses_null_and_values_of_the_wrong_type`,
    `settings_commands_refuse_malformed_arguments`,
    `a_malformed_file_is_refused_when_the_store_opens` (not UTF-8, TOML syntax, a table
    where a value belongs, the project's file), `an_undo_that_cannot_write_its_file_stays_in_line`,
    `a_log_filter_with_awkward_characters_round_trips`, `every_settings_command_has_its_schema`,
    `reading_settings_leaves_the_history_and_the_files_alone`, and the properties
    `a_settings_file_round_trips` and `a_put_value_is_the_value_got`.
- **Defects found:**
  - **P2-147**: `Session<C>` and `Registry<C>` are not `Send` for any context, although
    `crates/qs-commands/README.md` says "a `Session<C>` is `Send` when `C` is, and can move
    to the thread an agent, MCP or ACP server runs on". The erased command,
    `Box<dyn ErasedCommand<C>>` in `src/registry.rs`, has no `Send` or `Sync` bound. A test
    calling `assert_send::<Session<Doc>>()` fails to compile with E0277. L6 (agent, MCP, ACP)
    builds on this property.
  - **P2-148**: `SettingsStore` reads each file once, at `open`, and every write
    serialises the whole in-memory file. A hand edit made after the store opened is
    overwritten by the next `settings.set` or `settings.reset` (reproduced: a filter changed
    by hand to `debug`, then `settings.set appearance.theme light`, leaves no `debug` in the
    file), and every write strips the file's comments, even a `settings.set` to the value the
    file already has, which the command reports as no change. P2-148 also adds the missing
    fuzz target for the settings file decoder.

  Neither defect has a committed test here: each would fail CI until fixed, and the bar
  forbids an ignored test. Each issue's environment field holds the reproduction, and its
  acceptance requires the regression test.

Also noted, not defects: the `Setting` schema describes each key only by its own name
(`` "`appearance.theme`." ``), not its summary, so an agent reading `commands.list` learns
the keys but not what they do; and `settings.set`'s `value` has an unconstrained schema,
the type being checked only when the command runs.
