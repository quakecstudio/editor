# Readiness: P1 L2 syntax (P1-R2)

- **Issue:** #55 (`P1-R2`)
- **Reviewer:** an independent Kiro agent session (`review-55b`) re-running this review; did
  not write the layer's code
- **Date:** 2026-10-17
- **Commit measured:** `92fd38a062c5ceb9207c2fc8fa714c6fda0ee4e4` (`main`; the head the
  Readiness run resolved)
- **Verdict:** Ready

The L2 syntax layer passes every bar in `docs/testing.md` and ADR-0009 for all four crates.
The first P1-R2 review (2026-10-16) found it not ready on two axes and filed the blocking
issue #360 (`P1-58`): TEST-3 (spec citations) was below 100% for all four crates, and TEST-2
(mutation) left nine qc-preproc survivors on the case-fold comparison unaccounted for. #360 is
now closed (merged in PR #364), and this re-run confirms both are resolved:

- **TEST-3 (spec citations): 100% for all four crates.** #360 narrowed each crate README's
  **Spec sections** line to the statements the crate actually implements, and added a
  `// spec <ID>:` citation for every remaining within-layer statement, with no new baseline
  entry for an L2 crate. The Readiness run (`cargo xtask readiness spec`) now reports qc-lexer
  47 of 47, qc-preproc 34 of 34, qc-syntax 13 of 13 and qc-project 18 of 18, all 100%.
- **TEST-2 (mutation): every crate at or above 90%, every survivor accounted for.** #360
  killed seven of the nine qc-preproc survivors with new tests (rewriting the case tie-break in
  `FsLoader::stored_name` and `MemoryLoader::folded` with `Iterator::min`, which leaves no
  operator to flip) and recorded the remaining two in `ratchets.toml` under `equivalent_mutants`
  with a reason each. The Readiness `mutation` job lists those two as the only survivors
  (qc-preproc 132 of 134 = 98.5%); the `ratchet` job counts them as equivalent and passes.

Coverage and stability were already strong and remain so: every crate clears the line bar
(90%) and the branch bar (80%), and flakes are zero (20 of 20 on Linux, macOS and Windows for
all four crates). The independent adversarial review (TEST-9) stands: the first P1-R2 session
added six adversarial lexer tests, all passing and merged (listed in section 5), and found no
behavioural defect; this re-run re-measured the whole layer from CI evidence and found no new
defect. The Readiness `ratchet` job passed all 28 checks.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** two independent Kiro agent sessions. `review-55` (2026-10-16)
  measured the layer, found it not ready, added six adversarial lexer tests and filed #360.
  `review-55b` (2026-10-17) re-ran the Readiness workflow after #360 merged, confirmed every
  bar is met from CI evidence, and committed the ratchet minimums. Neither wrote the layer's
  code.
- **Tests added** (six, all passing, kept in the prior PR; `crates/qc-lexer/src/tests.rs`):
  - `reviewer_frame_list_separators_terminate` (QC-8.9): a `$frame` line full of `,`/`;`, which
    id's `qcc` loops on forever, terminates here with one E0503 per separator and the next line
    parses normally.
  - `reviewer_frame_name_length_boundary` (QC-27.6): a 15-byte frame name is silent, 16 bytes is
    the first that warns W0101, the exact `QC_MAX_FRAME_NAME` boundary.
  - `reviewer_short_vector_is_zero_filled` (QC-5.1): a vector with fewer than three components
    zero-fills the rest and reports E0104 without reading past end of file; a bare `'` is a zero
    vector with one E0104.
  - `reviewer_name_length_boundary_is_exact` (QC-27.4): `QC_MAX_TOKEN - 1` name bytes are fine,
    `QC_MAX_TOKEN` is E0502, and the over-long token is still produced in full.
  - `reviewer_block_comment_boundaries` (QC-2.3): `/**/` is empty, `/*/x` is a whole comment (the
    `*/` is found one byte past the first `/`), and `/* x` with no close is E0501.
  - `reviewer_punctuation_maximal_munch` (QC-7.1): the lexer tries multi-byte punctuation first,
    so `&&` beats `&`, `&&&` is `&&` then `&`, and `...` beats `.`.
- **Defects found:** the first review found the two blocking measurement defects (TEST-3
  spec-citation gaps and the qc-preproc TEST-2 survivors), filed as #360 and now fixed and
  merged. No behavioural defect was found in either session. The re-run found nothing new.
