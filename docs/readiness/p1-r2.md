# Readiness: P1 L2 syntax (P1-R2)

- **Issue:** #55 (`P1-R2`)
- **Reviewer:** an independent Kiro agent session (`review-55`) started for this review; did not write the layer's code
- **Date:** 2026-10-16
- **Commit measured:** `c5b56daef0db6561b1219d5b078ed497eefa655c` (`main`; the commit the Readiness run resolved)
- **Verdict:** Not ready

The layer is strong on coverage and stability: every crate clears the line bar (90%) and the
branch bar (80%) on the pinned nightly, and flakes are zero (20 of 20 on Linux, macOS and
Windows for all four crates). It does not pass because two requirements are unmet:

- **TEST-3 (spec citations) fails for all four crates.** The authoritative measurement (`cargo
  xtask readiness spec`) reports qc-lexer 73.3%, qc-preproc 79.0%, qc-syntax 60.4% and
  qc-project 64.5%. The bar is 100% with no baseline backlog for a new crate. 92 active
  statements that the crate READMEs list under **Spec sections** have no `// spec` test citation
  in the crate. Most are statements that belong to a higher layer (name resolution, type
  checking and code generation), which the syntax layer does not implement; a few (such as
  QC-8.9) are genuinely this layer's. Resolving it means narrowing each README's declared
  **Spec sections** to the statements the crate actually implements, or adding the missing
  citations; this is for the owning work, not the reviewer.
- **TEST-2 (mutation) fails for qc-preproc.** 9 surviving mutants (93.6%, above the 90% bar but
  below the "every survivor accounted for" rule) are neither killed by a test nor recorded in
  `ratchets.toml` under `equivalent_mutants`. qc-lexer, qc-syntax and qc-project all reach 100%
  mutation with no survivors.

This review added six adversarial tests (TEST-9) to qc-lexer, all passing; they found no
behaviour that disagreed with the spec. The spec-citation gaps and the qc-preproc survivors are
filed as the blocking issue and must be fixed before P1-R2 can close.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Kiro agent session (`review-55`), one working
  session on 2026-10-16. Built and tested all four L2 crates locally, measured coverage, spec
  citations and mutation, dispatched and read the Readiness workflow, and probed the lexer's
  edges against `docs/spec/language.md`.
- **Tests added** (six, all passing, kept in this PR; `crates/qc-lexer/src/tests.rs`):
  - `reviewer_frame_list_separators_terminate` (QC-8.9): a `$frame` line full of `,`/`;`, which
    id's `qcc` loops on forever, terminates here with one E0503 per separator and the next line
    parses normally.
  - `reviewer_frame_name_length_boundary` (QC-27.6): a 15-byte frame name is silent, 16 bytes is
    the first that warns W0101, the exact `QC_MAX_FRAME_NAME` boundary.
  - `reviewer_short_vector_is_zero_filled` (QC-5.1): a vector with fewer than three components
    zero-fills the rest and reports E0104 without reading past end of file; a bare `'` is a zero
    vector with one E0104.
  - `reviewer_name_length_boundary_is_exact` (QC-27.4): `QC_MAX_TOKEN - 1` name bytes are fine,
    `QC_MAX_TOKEN` is E0502, and the over-long token is still produced in full.
  - `reviewer_block_comment_boundaries` (QC-2.3): `/**/` is empty, `/*/x` is a whole comment (the
    `*/` is found one byte past the first `/`), and `/* x` with no close is E0501.
  - `reviewer_punctuation_maximal_munch` (QC-7.1): the lexer tries multi-byte punctuation first,
    so `&&` beats `&`, `&&&` is `&&` then `&`, and `...` beats `.`.
- **Defects found:** no behavioural defect. Every adversarial probe agreed with the spec (one,
  the block-comment test, started from a wrong premise about `/*/` and was corrected to match
  QC-2.3, which the existing tests already pin, before it passed). The blocking defects are the
  measured TEST-3 spec-citation gaps and the qc-preproc TEST-2 survivors in section 2, filed as
  P1-58.
