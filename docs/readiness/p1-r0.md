# Readiness: P1 L0 formats (P1-R0)

- **Issue:** #53 (`P1-R0`)
- **Reviewer:** an independent Kiro agent session (`review-53`) started for this review; did not write the layer's code
- **Date:** 2026-10-16
- **Commit measured:** `8a819e5c824c2ffc9ec7ed70acc8c2fecad0d5d2` (`main`; the commit the Readiness run resolved)
- **Verdict:** Not ready

The layer is largely strong: every crate clears the line and branch coverage bars on all three
OSes, flakes are zero (20 of 20 on Linux, macOS and Windows for every crate), and most crates
reach the mutation and spec bars. It does not pass because TEST-2 (mutation) and TEST-3 (spec
citations) are not met for several crates:

- Surviving mutants that are neither killed by a test nor recorded in `ratchets.toml` under
  `equivalent_mutants` exist in eight crates: `qc-progs` (1), `qc-lno` (9, below the 90% bar at
  76.3%), `qs-vfs` (1), `qs-log` (4), `qs-install` (12), `qs-bsp` (15), `qs-map` (45) and
  `qs-mdl` (10). TEST-2 requires every survivor accounted for.
- The authoritative spec-citation measurement (`cargo xtask readiness spec`) reports `qc-progs`
  at 90.7% and `qc-lno` at 52.6%: statements the crate READMEs list under their **Spec sections**
  are not cited by a test in the crate (they sit in `docs/spec/coverage-baseline.tsv`). TEST-3
  allows no baseline backlog for new crates.
- `cargo xtask readiness spec` cannot measure `qs-log`: its only README spec section is QA-7,
  which has no active statements in `docs/spec/requirements.tsv`, so the tool errors and the
  Readiness ratchet step cannot judge that crate.
- The Readiness mutation job itself did not finish (it ended with exit code 143 after `qs-map`,
  before `qs-mdl` and `qs-wav`), so the layer has never had a complete mutation measurement in
  CI. This review measured `qs-mdl` and `qs-wav` locally to fill the gap.

This review added adversarial tests (TEST-9) in `qc-lno` (killing five of its nine survivors),
`qs-pak`, `qs-wad` and `qs-wav`, all passing. The remaining survivors and spec gaps are filed as
blocking issue P1-57 and must be fixed before P1-R0 can close.

Spec-citation gaps (TEST-3). `cargo xtask readiness spec` attributes to a crate every active
statement of the sections its README lists. The uncited statements are:

- `qc-progs` (5): `PROGS-5.1`, `PROGS-5.2`, `PROGS-5.3`, `PROGS-6.2`, `PROGS-10.3`. The README
  says these "belong to the compiler, the server and the VM"; they are in
  `docs/spec/coverage-baseline.tsv`.
- `qc-lno` (9): `LNO-1.1` to `LNO-1.6`, `LNO-4.4`, `LNO-4.5`, `LNO-6.4`. The README says LNO-1
  "belongs to the compiler" and LNO-4.4/4.5 to "the line-number reader"; all are in the baseline.

These are not citations this crate's tests can add (the behaviour is another crate's). Resolving
TEST-3 for the two crates means narrowing each README's declared **Spec sections** to the
statements the crate actually implements (so the readiness tool stops attributing the others to
it), or recording the split another way; this is for the owning work, not the reviewer, and is
part of P1-57.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Kiro agent session (`review-53`), one working
  session on 2026-10-16. Built and tested every L0 crate locally, re-ran `cargo mutants` on
  `qc-lno`, `qs-mdl` and `qs-wav`, and probed spec edges.
- **Tests added** (all passing, kept in this PR; ten new tests across four crates):
  - `crates/qc-lno/src/tests.rs`: `reviewer_read_error_messages`, `reviewer_write_error_messages`,
    `reviewer_match_error_messages`, `reviewer_matches_header_reports_a_mismatch`. These kill five
    of the nine mutation survivors (the four `Display::fmt` bodies the mutant replaced with
    `Ok(())`, and `matches_header` which the mutant made return `Ok(())` unconditionally). After
    them, `cargo mutants` on `qc-lno` reports 4 missed (down from 9), 34 caught of 38.
  - `crates/qs-pak/src/tests.rs`: `reviewer_extreme_entry_range_is_listed_but_unreadable`
    (PAK-2.12, PAK-3.4: a `filepos`/`filelen` of `i32::MAX` is listed but unreadable, with no
    64-bit overflow) and `reviewer_full_directory_past_eof_fails_out_of_bounds` (PAK-2.4, PAK-2.6,
    PAK-2.7: a 131072-byte directory one byte past the file fails as out of bounds, not too large,
    confirming id's check order).
  - `crates/qs-wad/src/tests.rs`: `reviewer_empty_named_lump_is_found_by_empty_name` (WAD-2.5,
    WAD-3.1: a lump whose name field starts with NUL cleans to the empty name and is found by an
    empty lookup; the first match wins).
  - `crates/qs-wav/src/tests.rs`: `reviewer_cue_loopstart_file_boundary` (WAV-2.6) and
    `reviewer_list_mark_file_boundary` (WAV-2.7): the exact one-byte file boundary at which the
    `loopstart` field and the `mark` tag fall past the end of the file.
- **Defects found:** the surviving mutants and the spec-citation gaps in section 2, all filed as
  P1-57. The adversarial probes against `qs-pak`, `qs-wad` and `qs-wav` found no behaviour that
  disagreed with the spec; those four tests passed on first run and are kept as regression tests
  (one, the `qs-wav` cue boundary, started from a wrong premise about chunk padding and was
  corrected to a file-length boundary before it passed).
