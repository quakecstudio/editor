# Readiness: P1 L0 formats (P1-R0)

- **Issue:** #53 (`P1-R0`)
- **Reviewer:** an independent Kiro agent session (`review-53b`) for this review; did not write the layer's code
- **Date:** 2026-10-17
- **Commit measured:** `110ce43` (`main`; the commit the Readiness re-run resolved)
- **Verdict:** Ready

The L0 formats layer passes the bar on every axis. The first P1-R0 review (2026-10-16) found
the layer not ready on TEST-2 (surviving mutants not killed or recorded) and TEST-3 (the
readiness spec tool penalised `qc-progs` and `qc-lno` for statements still in the coverage
baseline), and filed blocking issue P1-57 (#358). That issue is now closed: PRs #361, #362, #363
and #365 killed or recorded every surviving mutant across the eight affected crates (`qc-progs`,
`qc-lno`, `qs-vfs`, `qs-log`, `qs-install`, `qs-bsp`, `qs-map`, `qs-mdl`), and PR #366 made
`cargo xtask readiness spec` baseline-aware so a statement deferred in
`docs/spec/coverage-baseline.tsv` is not counted against the crate that does not yet own it.

The Readiness re-run [39024658466](https://github.com/quakecstudio/editor/actions/runs/39024658466)
measured all 13 L0 crates on `main` and reports `ratchet: 91 checks passed`: every crate clears
lines (bar 90%), branches (bar 80%), mutation (bar 90%, or a recorded exception for `qc-lno`),
spec citations (100%), and 20 of 20 flake runs on Linux, macOS and Windows. The mutation job,
which failed with exit 143 in the earlier run, completed successfully this time.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Kiro agent session (`review-53b`), one working
  session on 2026-10-17, re-running P1-R0 after P1-57 (#358) closed. It did not write the layer's
  code. The first P1-R0 review (`review-53`, 2026-10-16) added ten adversarial tests across
  `qc-lno`, `qs-pak`, `qs-wad` and `qs-wav`; those landed on `main` with the P1-57 PRs and are
  kept as regression tests.
- **Tests added by this re-review** (kept in this PR):
  - `crates/qs-mdl/src/mdl/tests.rs`: `reviewer_gl_limits_all_four_exceeded_report_in_order`
    (MDL-1.8). A model that exceeds every GLQuake limit at once reports all four in the push order
    vertices, skins, triangles, poses. The per-limit tests pin each branch alone; this pins that
    the four checks are independent and all fire together, so a mutant that drops or short-circuits
    one branch is caught even when the others are over the limit too. Verified to fail when the
    triangles branch is disabled, then to pass 20 of 20 with the branch restored.
- **Defects found by this re-review:** none. The three blocking defects of the first review
  (surviving mutants, spec-citation gaps, the mutation job's exit 143) are all resolved and the
  Readiness re-run passes every axis.
