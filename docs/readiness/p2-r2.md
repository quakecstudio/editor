# Readiness: P2 L2 syntax (P2-R2)

- **Issue:** #83 (`P2-R2`)
- **Reviewer:** an independent Claude agent session (the `reviewer` subagent); did not write
  the layer's code
- **Date:** 2026-10-20
- **Commit measured:** `368abee8a31940dbdf6b01a32bf9b4a15a4601aa` (`main`, after #446) for
  qc-preproc, qc-syntax and qc-project, and `a82c1c05ec5131e517c0343d012881ff7eac1d54`
  (`main`, after #458) for qc-lexer; #458 changed only qc-lexer's tests
- **Verdict:** Not ready

This is the second review of the layer. The first (commit `58c060c`, run
[39303208067](https://github.com/quakecstudio/editor/actions/runs/39303208067)) found it not
ready; #438 and #446 have since landed. The first review's defects are fixed: no FTEQCC
construct overflows the parser's stack any more (P2-50, #433), the FTEQCC profile is fuzzed and
property-tested (P2-51, #434), and vector suffixes and enum types read as FTEQCC reads them
(P2-59, #450). Every crate is back at or above the minimums P1-R2 committed to
`ratchets.toml`: the run on `368abee` for qc-preproc, qc-syntax and qc-project, and for
qc-lexer, whose branches that run measured at 98.3% (232 of 236), the run on `a82c1c0`
after #458 (P2-63, #460) covered the four, at 100% (236 of 236).

The layer is not ready, on two defects this review found:

- **P2-65, preprocessor stack overflow (`type:feature`).** A chain of object-like macros, each
  defined as the name of the one before (`#define M1 M0`, `#define M2 M1`, ...), aborts the
  process with a stack overflow in `Preprocessor::preprocess_file` under both dialects: at
  10000 macros in a debug test thread, at 100000 in a release build (30000 expand). The same
  10001-line file through `qc_sema::Db::analyze_module` aborts the semantic model, so one source
  file can take the editor down. QC-27.15 and PRJ-5.10 state the project's rule that no input
  can exhaust a stack.
- **P2-66, FTEQCC builtin initialisers (`type:feature`).** The pinned FTEQCC compiles
  `void(string s, ...) bp = #"ex_bprint";` and `... br = :ex_bprint3;` with no warning
  (`QCC_PR_ParseInitializerType_Internal` takes `#` or `:` and then a number, a string,
  `else if (pr_token_type == tt_immediate && pr_immediate_type == type_string)`, or a name,
  `else if (pr_token_type == tt_name)`), but the
  FTEQCC profile reports E0209 "Bad builtin immediate" and E0201 "not a name". FTE-17.4 lists
  only `#number` and `#number:name`. No corpus file uses either form.

Each defect is filed as a blocking issue (section 5); the review added ten
passing tests.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Claude agent session, about three hours across
  both P2 re-reviews. It put 70 deep and long constructs, 100000 repeats each, through the
  parser under both profiles in debug and release builds, measuring tree depth, the nesting
  error and the round trip; 25 deep and long preprocessor inputs and 13 project-graph inputs
  through `qc-preproc` and `qc-project`; and FTEQCC's preprocessor and builtin behaviour through
  the pinned FTEQCC oracle (`cargo xtask oracles build`) and its source at
  `f937b9d88f71fc4429db5fe56c6a98d922711b2e`.
- **The first review's defect, re-checked:** none of the 70 forms overflows the parser at
  100000 repeats in a debug build, and each one gives back its bytes. Every tree's depth is the
  same at 50000 and 100000 repeats: 773 at most for the FTEQCC forms the first review measured
  growing (nested `struct {`), and for the deepest form, a function body nested in function
  bodies, 1023 under FTEQCC and 1027 under vanilla, where recovery rather than E0509 bounds it. Every FTEQCC form that
  nests reports E0509.
- **Behaviour checked against FTEQCC and found to agree:** `#define f(x) x` and `f(f(1))`
  leave the inner `f` unexpanded in both (FTEQCC: `Unknown value "f"`), though FTEQCC's
  `QCC_PR_CheckCompConst` allows a macro to re-enter itself up to eight levels (`if
  (c->inside >= 8)`); an open `#ifndef` at the end of a file is silent under FTEQCC
  (FTEF-14.10); `#if M1` with `#define M1 M0` reads the text `M0` as 0 (FTEF-14.11).
- **Tests added** (ten, all passing):
  - `crates/qc-syntax/src/tests/reviewer.rs`:
    - `reviewer_fteqcc_aggregate_nesting_is_bounded` (QC-27.15): a struct or union nested
      100000 deep, and an unclosed one.
    - `reviewer_fteqcc_initialiser_lists_are_bounded` (QC-27.15): `{` lists 100000 deep.
    - `reviewer_fteqcc_right_nesting_chains_are_bounded` (QC-27.15): `?:` in its middle, `=`
      and `+=` chains, `~`, prefix `*` and postfix `++`, 100000 each.
    - `reviewer_fteqcc_file_scope_expressions_are_bounded` (FTEF-18.26): an enum value, a
      parameter default and a global initialiser nested 100000 deep.
  - `crates/qc-preproc/src/tests/fteqcc.rs`:
    - `reviewer_open_blocks_at_the_end_of_a_file` (FTEF-14.10, QC-9.12): of three open
      blocks, FTEQCC reports only the skipped one, vanilla all three.
    - `reviewer_deep_conditionals_nest_and_close` (QC-9.6): 100000 nested `#ifdef`/`#ifndef`
      under both profiles.
    - `reviewer_a_chain_of_macros_expands_to_its_end` (QC-9.4): a 1000-long chain, one
      expansion each, under both profiles; P2-65 is the same at 100000.
  - `crates/qc-project/src/tests/forms.rs`:
    `reviewer_a_long_includelist_chain_stops_at_the_depth_limit` (PRJ-6.3, QCD-5.8): 5000
    files each listing the next stop at `PRJ_MAX_DEPTH` with one E0408.
  - `crates/qc-lexer/src/tests.rs`: `reviewer_fteqcc_spans_are_ordered_and_in_bounds` and
    `reviewer_fteqcc_token_text_relexes`, the README's first two invariants under the FTEQCC
    profile (TEST-4).
- **Defects found** (each blocks readiness; issues in `plan/backlog/p2.yaml`, synced to GitHub
  after this PR merges):
  - **P2-65, preprocessor stack overflow (`type:feature`):** above.
  - **P2-66, FTEQCC builtin initialisers (`type:feature`):** above. Keying those builtins by
    name in the engine-target check is the L3 half, P2-67 (`docs/readiness/p2-r3.md`).
