# Readiness: P2 L2 syntax (P2-R2)

- **Issue:** #83 (`P2-R2`)
- **Reviewer:** an independent Claude agent session (the `reviewer` subagent); did not write
  the layer's code
- **Date:** 2026-10-23
- **Commit measured:** `40f42b054771cbd973c34b9a37001853a8e788f2` (`main`, after #533), all
  four crates
- **Verdict:** Not ready

This is the sixth review of the layer. The fifth (commit `6f12aef`) was blocked on P2-107 to
P2-109. Since then #532, #537, #541, #547 and #533 closed P2-107 to P2-112, P2-114, P2-116 and
P2-109, and #555 and #557 ported FTEQCC's keyword flags (P2-119) and its flags that change in the
middle of a file, `extern "C"` and `extern "QC"` blocks among them (P2-121). Every issue the
readiness issue depends on was closed when this review started.

The Readiness run on `40f42b0` met every number of the bar and every ratchet for all four
crates: lines, branches, mutation, spec citations and 20 of 20 runs on each OS (`ratchet: 28
checks passed`). The mutation job, now one runner per crate with a memory limit per test binary
(#533), finished for the first time since the FTEQCC directive port.

This review ran 506 programs of its own through the builtin differential against the pinned
FTEQCC: 464 agree and 42 differ. 18 of the differences are defects of this layer's parser, in
two classes, filed here as P2-130 and P2-131, and the review also found that nested `extern`
blocks overflow the parser's stack (P2-130). Each blocks readiness. 11 more are a defect of the
semantic model, filed as P2-132 against P2-R3, and the other 13 are divergences the spec states.

- **P2-130, `extern` blocks (`type:feature`).** The parser's `extern_block` recurses with no
  nesting level, so 5000 nested `extern "C" { ` overflow a 2 MiB thread's stack; it takes
  `extern "C"` with no definition at the end of a file, and `extern "C" { ; }`, which FTEQCC
  refuses; and it compares the linkage past a NUL and across macro expansions, where
  `strcasecmp(pr_token, "C")` stops at the NUL of the one string token the lexer read.
- **P2-131, type names under `caseinsens` (`type:feature`).** Under `-Fcaseinsens` FTEQCC finds
  a type name in any case, so `Float x;`, `VECTOR v;` and `__Int x;` in a body define locals; the
  parser reads each as an expression.

The review added six passing tests.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Claude agent session, about three hours of work.
  It built the oracles on macOS arm64 (`cargo xtask oracles build`), read the command line,
  pragma, keyword, `extern` and file-loader code of #532 to #557 against `qccmain.c`,
  `qcc_pr_lex.c`, `qcc_pr_comp.c` and `qcc_cmdlib.c` at the pinned commit, ran the 506 programs
  of section 3, and parsed nested forms of every construct #555 and #557 added (`loop`, `until`,
  `using`, `asm`, `if not`, `state`, labels, `case`, attributes, accessors, classes, enums,
  typedefs, C function pointers and parameter lists, `sizeof`, `extern`), 100000 deep, under the
  FTEQCC profile on a 2 MiB test thread.
- **Defects found** (each blocks readiness; issues in `plan/backlog/p2.yaml`, created on GitHub
  by `plan/apply.py` after this PR merges, with the FTEQCC source quoted there). Each row is
  FTEQCC's outcome against the profile's:

  | Program | FTEQCC | Profile | Issue |
  | --- | --- | --- | --- |
  | 5000 nested `extern "C" { ` and `}`, or 100000 `extern "C" ` before `float x;`, at file level or in a body | (recursion) | the parser's stack overflows: `fatal runtime error: stack overflow` | P2-130 |
  | 500 nested `extern "C" { ` and `}` | | no "nesting too deep" (QC-27.15) | P2-130 |
  | `extern "C"`, `extern "C";`, `extern "C" ;;;` or `extern "C" "QC"` at the end of the file | `"" is not a type` | accepted | P2-130 |
  | `extern "C" { ; }` | `"}" is not a type` | accepted | P2-130 |
  | `extern "C\x00x" { string s = "\9"; }`, and `extern "C":"x" { ... }` under `qccx` | a `"C"` block: "Bad character code \9" | no `"C"` block, accepted | P2-130 |
  | `#define C "C"`, then `extern C C { string s = "\9"; }` | `"C" is not a type` | the block `"CC"`, accepted | P2-130 |
  | under `-Fcaseinsens`, `void() g = { Float x; };`, `{ VECTOR v; }`, `{ Entity e; }`, `{ String s; }`, `{ FLOAT x; x = 1; }`, `{ __Int x; }`, `{ Float; }`, `{ for (Float i = 0; i < 1; i++) {} }` | a local defined, compiled | E0204 "expected ;, found x", E0301 "Unknown value" | P2-131 |

  semantic model's start of the second autoprototyping pass (`#pragma autoproto` after `float

  `assumevar` a late pragma leaves for the second pass) and `Void()` under `-Fcaseinsens`.
