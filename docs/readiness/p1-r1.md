# Readiness: P1 L1 VM (P1-R1)

- **Issue:** #54 (`P1-R1`)
- **Reviewer:** an independent Kiro agent session (`review-54b`) for this review; did not write the layer's code
- **Date:** 2026-10-17
- **Commit measured:** `63b5526` (`main`; the commit the Readiness run resolved)
- **Verdict:** Ready

The L1 VM layer meets the ADR-0009 bar on every crate and every axis. The Readiness run
[39062046197](https://github.com/quakecstudio/editor/actions/runs/39062046197) on `main`, for
`crates="qc-vm qc-builtins qc-edict qc-trace qs-porting-example"`, measured coverage, mutation,
spec citations and 20 flake runs on each OS. Every line, branch, mutation and spec number is at
or above the bar, and the one surviving mutant is recorded as equivalent with its reason.

This is the re-run after the prior review found the layer not ready and filed blocking issue
P1-65 (#393, now closed, merged as PR #394). That work raised `qc-builtins` line coverage from
67.7% to 94.5% and mutation from 63.4% to 97.4%, raised `qc-edict` line coverage from 85.8% to
96.9% and killed its last mutation survivors (100%), raised `qc-vm` mutation from 85.7% to 91.7%,
and rewrote the `qc-vm` and `qc-builtins` README `Spec sections` lines in the `- **Spec
sections:**` form the readiness spec tool parses, so spec citations now measure 100% for all five
crates.

Every axis is at or above the ADR-0009 bar (lines 90%, branches 80%, mutation 90%, spec 100%).

Surviving mutants (TEST-2). The `cargo xtask ratchet` step requires every survivor to be killed
by a test or recorded in `ratchets.toml` under `equivalent_mutants` with a reason.

- `qc-edict` and `qs-porting-example`: zero survivors.
- `qc-vm` (19 survivors) and `qc-builtins` (19 survivors): each is recorded equivalent in
  `ratchets.toml` (the tables set by P1-65, #393), with per-mutant reasons citing the spec. They
  are guards whose only distinguishing value is rejected downstream by the same store bounds
  check, OR over disjoint flag bits where `|` equals `^`, comparison boundaries whose equal case
  reassigns the same value, the float-to-int sign split that gives +0 at zero either way, and the
  trait default that already returns None. The reviewer re-derived the `| -> ^` disjoint-bit and
  the `< -> <=` downstream-rejected cases independently and agrees they are equivalent.
- `qc-trace` (1 survivor): `crates/qc-trace/src/binary.rs: replace | with ^ in put_uvar`. The
  continuation byte is `group | 0x80`, where `group = (value & 0x7F).to_le_bytes()[0]` is masked
  to seven bits, so bit `0x80` of `group` is always clear and `group | 0x80 == group ^ 0x80` for
  every input: the LEB128 bytes are byte-identical. No test can distinguish the two operators
  (the multi-byte vectors `uvar_bytes(128)=[0x80,0x01]`, `uvar_bytes(300)=[0xac,0x02]` and
  `uvar_bytes(u32::MAX)=[0xff,0xff,0xff,0xff,0x0f]` pass under both), so it is recorded equivalent
  in `ratchets.toml` with that reason (TRACE-5.1), not killed. This was the one item the prior
  `ratchet` run flagged; it is now recorded.

ADR-0013 (2026-10-17) sets the differential VM suite's bar. Its text, verbatim:

> Decided: **option C.** The differential VM suite's hard bar is **zero divergences on every
> corpus codebase**, enforced in CI (QA-1): the fast subset on id 1.01 on every change, the full
> corpus nightly. The suite continues to **measure and report** statement coverage by DIFF-11.1
> to DIFF-11.3, but does not gate on a flat 90% figure, because the mock engine is specified
> (DIFF-5.8, DIFF-1.5) not to drive the running world [...]

So for the VM oracle the flat 90%-statements figure of TEST-6 does not apply; zero divergences
is the gate. That bar is met on id 1.01 (per #388, "id-1.01: 4 scenarios, 0 divergences"). The
flat 90% still applies to the other oracles, none of which is an L1 crate. `qs-differential` is
the harness (layer `tests`) and is not gated here.

  - `q_atof_spec_examples_and_empty_prefixes` (BUILTIN-11.7): pins the spec's own normative
    example that `Q_atof` has no exponent (`"1e3"` is 1), and the empty-tail edges its two
    prefixes allow (`"0x"` with no hex digit is 0, a lone `"'"` with no following character is 0,

    it before.

  coverage and mutation, `qc-vm` mutation, `qc-edict` coverage, and the two README `Spec sections`

  mutant (proved in section 2) and is recorded, not a defect.

The adversarial tests pin behaviour the code already gets right and are kept as regression
tests. None of them failed on the current code.
