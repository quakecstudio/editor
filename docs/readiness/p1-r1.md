# Readiness: P1 L1 VM (P1-R1)

- **Issue:** #54 (`P1-R1`)
- **Reviewer:** an independent Kiro agent session (`review-54`) for this review; did not write the layer's code
- **Date:** 2026-10-17
- **Commit measured:** `1c01300` (`main`; the commit the Readiness run resolved)
- **Verdict:** Not ready

The L1 VM layer does not meet the ADR-0009 bar. The Readiness run
[39053374755](https://github.com/quakecstudio/editor/actions/runs/39053374755) on `main`, for
`crates="qc-vm qc-builtins qc-edict qc-trace qs-porting-example"`, measured coverage, mutation
and 20 flake runs on each OS successfully, but `cargo xtask ratchet` did not pass: three axes
are short of the bar.

- **TEST-1 (coverage):** `qc-builtins` is at 67.7% lines and 52.0% branches, far below the 90%
  line and 80% branch bars; `qc-edict` is at 85.8% lines, below the 90% line bar.
- **TEST-2 (mutation):** `qc-builtins` has 272 surviving mutants (63.4%) and `qc-vm` has 33
  (85.7%), both below the 90% bar with survivors neither killed nor recorded equivalent.
- **TEST-3 (spec citations):** could not be measured. `cargo xtask readiness spec` exits 1 on
  `crates/qc-vm/README.md` with "no `**Spec sections:**` line", because `qc-vm` and
  `qc-builtins` write the heading as a Markdown header (`## Spec sections [implemented]`) rather
  than the bold inline `- **Spec sections:** ...` line the tool parses.

`qc-trace` and `qs-porting-example` meet the bar on every measured axis. The defects are filed
as blocking issue **P1-65** (#NNN, set after sync), on which this review (#54) and the P1 gate
(#49) depend.

ADR-0013 (2026-10-17) revised the differential VM suite's bar. Its text, verbatim:

> Decided: **option C.** The differential VM suite's hard bar is **zero divergences on every
> corpus codebase**, enforced in CI (QA-1): the fast subset on id 1.01 on every change, the full
> corpus nightly. The suite continues to **measure and report** statement coverage by DIFF-11.1
> to DIFF-11.3, but does not gate on a flat 90% figure, because the mock engine is specified

an L1 crate.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Kiro agent session (`review-54`), one working
  session on 2026-10-17. It did not write the layer's code.
- **Tests added** (kept in this PR, `crates/qc-vm/src/tests/adversarial.rs`), all passing and
  clippy-clean:
  - `nested_run_has_its_own_runaway_counter` (LIMIT-4.2): a nested `PR_ExecuteProgram` whose body
    is an infinite `GOTO 0` fails with `runaway loop error` on its own fresh counter, raised in
    the nested function, while the outer run executed only two statements. Pins the complement of
    the `runaway_per_run` vector.
  - `stack_overflow_keeps_the_local_stack` (VM-19.3): a deep recursion whose functions have
    locals fails with `stack overflow`, after which `depth()` is 0 but `localstack_used()` is
    greater than 0 (the aborted frames' locals are kept). The `stack_overflow` vector records
    `localstack=0` because its function has no locals; this pins the non-empty half.
  - `machine_reused_after_an_aborted_run_still_runs_cleanly` (VM-1.1, VM-19.3): a run aborted by a
    bad opcode leaves depth 0; a fresh run on a clean machine starts at depth 0 and completes
    correctly.
  - `done_does_not_fall_through_into_the_next_statement` (VM-16.4): a `DONE` as the entry
    function's only statement ends the run; a store laid out physically after it never executes.
  - `engine_string_resolves_inside_a_nested_run` (VM-7.3): `EQ_S` of two engine-allocated string
    values resolves through the `Builtins` dispatch even when the comparison happens inside a
    nested `PR_ExecuteProgram`, because the dispatch is threaded through `Context::execute_program`.
- **Defects found (each blocks readiness, all filed under P1-65):**
  1. `qc-builtins` coverage far below the bar (67.7% lines, 52.0% branches) and mutation 63.4%
     (272 survivors): the mock-engine dispatch bodies lack tests (TEST-1, TEST-2).
  2. `qc-vm` mutation 85.7% (33 survivors) below the 90% bar (TEST-2).
  3. `qc-edict` lines 85.8% below the 90% bar, with 7 unaddressed mutation survivors (TEST-1,
     TEST-2).
  4. `qc-vm` and `qc-builtins` READMEs use a Markdown header instead of the `- **Spec sections:**`
     line the readiness spec tool parses, so TEST-3 could not be measured for the layer.

The adversarial tests the reviewer added pass on the current code: they pin behaviour the VM
already gets right and are kept as regression tests. They do not raise `qc-builtins` or
`qc-edict` to the bar; closing the gap is the owning crates' work under P1-65.
