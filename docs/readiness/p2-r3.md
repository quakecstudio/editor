# Readiness: P2 L3 semantics (P2-R3)

- **Issue:** #84 (`P2-R3`)
- **Reviewer:** an independent Claude agent session (the `reviewer` subagent); did not write
  the layer's code
- **Date:** 2026-10-19
- **Commit measured:** `58c060c12c4ba72f0874dd738fab09a00fe700e6` (`main`; the head the
  Readiness run resolved)
- **Verdict:** Not ready

The L3 semantics layer does not pass the bar in `docs/testing.md` and ADR-0009. Coverage of
lines, spec citations as measured, and flakes are fine, but:

- **TEST-1 (branches):** qc-sema is at 74.2%, below the 80% bar.
- **TEST-2 (mutation):** qc-sema is at 81.1%, below the 90% bar, with 52 survivors neither
  killed nor listed as equivalent; qc-engines is at 93.3% but has three unaccounted survivors.
  The Readiness `ratchet` job fails on all three.
- **TEST-3 (spec citations):** qc-sema's 51 of 51 holds only because the workflow excludes six
  statements of its declared sections that sit in `docs/spec/coverage-baseline.tsv`, which a
  new crate may not rely on; one of them (QC-12.6) is behaviour qc-sema implements.
- **TEST-4, TEST-5, TEST-6:** qc-sema has no property test, no fuzz target drives the semantic
  model or the engine-target check, and the layer note's golden corpus indexes and a
  differential against the oracle compilers' definitions do not exist.
- **A behavioural defect:** lowering a function type whose parameter is a function type is
  exponential in the depth, so one line such as `void(void(void(...` hangs the model.

Each is filed as a blocking issue (section 5); the review added eight passing tests.

What does exist: `cargo xtask fteqcc-profile` in the corpus job resolves the six rerelease
codebases (Linux) and FreeCS, Rad-Therapy, Nuclide's `menu-fn`, Copper and Arcane Dimensions

file. The layer note in `docs/testing.md` asks for more: golden indexes (definitions,
references, diagnostics) for the corpus. The reviewer ran id 1.01 through `Db::analyze_module`
locally: under the vanilla profile 3314 definitions, 15924 references and one diagnostic
(`W0201`, `local float enemy_yaw` in `fight.qc`, QC-12.3); under the FTEQCC profile two `W0106`
duplicate frame macros (`attackb1` in `knight.qc`, `shake12` in `oldone.qc`) and one `W0313`
(`self.speed == 1000;` in `misc.qc`), each a real instance of what it reports. That run is
evidence the model reads id 1.01, but it is not in CI and nothing pins its numbers (P2-47).

Incrementality, the other half of the layer note, is asserted by query counters in
`src/tests/incremental.rs` and `src/tests/expansion.rs`.

TEST-8 (performance): the `keystroke` budget in `docs/perf-budgets.md` (P2-18) is `pending`;
no budget applies to an L3 crate yet. The exponential lowering below would break it.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Claude agent session, about two hours across
  both P2 reviews, measuring from CI and probing the crates with generated inputs (deep and long
  constructs under both profiles, id 1.01 end to end).
- **Tests added** (eight, all passing):
  - `crates/qc-sema/src/tests/reviewer.rs`:
    - `reviewer_goto_definition_covers_exactly_the_name` (QC-12.5): the first and last byte
      of a use hit, the bytes before and after do not.
    - `reviewer_goto_definition_is_per_file` (QC-12.5): the same offset in another file of
      the module finds nothing.
    - `reviewer_nested_function_types_compare_without_names` (QC-10.6): a prototype and a
      body whose function-typed parameter is named differently are one function, with the
      inner and field parameter types lowered.
    - `reviewer_type_name_goes_through_a_pointer` (FTEF-17.3).
    - `reviewer_file_paths_are_kept`: `Db::file_path` for a file set with and without a path.
    - `reviewer_member_before_global` (FTEF-17.1): in a member function a class member is
      found before a global of the same name.
  - `crates/qc-engines/src/tests.rs`:
    - `reviewer_only_all_zero_digits_key_by_name` (ENGT-4.5): `#00`, `#0.0`, `#00.0` key by
      name; `#0.5`, `#0.01`, `#00.10` give no key and no `W0311`.
    - `reviewer_the_name_follows_the_colon` (ENGT-4.5): `# 0 : nothing` is keyed by `nothing`.
- **Defects found** (each blocks readiness; issues in `plan/backlog/p2.yaml`, synced to GitHub
  after this PR merges):
  - **P2-45, exponential type lowering (`type:feature`).** `Type::params_of`
    (`crates/qc-sema/src/ty.rs`) lowers a lone unnamed parameter's type twice, once to test for
    `(void)` and again for the result, so a function type whose parameter is a function type
    costs 2^depth. Resolving the one-line file `void(void(...void f;` took 102 ms with 16
    `void(`, 469 ms with 18, 2.1 s with 20 (both profiles, debug build), and did not finish in
    120 s with 300, so typing such a line hangs the semantic model.
  - **P2-46, the bar for qc-sema and qc-engines (`type:test`):** the branch and mutation
    numbers and survivors above, the six baseline statements in qc-sema's sections, and
    ENGT-4.5's "any literal whose digits are all zeros", which does not say whether FTEQCC's
    `#0x0:NAME` is a zero (`engine_name` says no).
  - **P2-47, corpus golden indexes, differential, properties and fuzzing (`type:test`).**
  - Found from here against the layer below and filed there: the FTEQCC profile of
    `qc-syntax` builds trees deeper than `QC_MAX_NESTING`, which overflow qc-sema's stack too
    (`a = ---...a;` with 3000 `-` aborts the test thread in `Db::module_index`; P2-43,
    `docs/readiness/p2-r2.md`).
