# Readiness: P2 L3 semantics (P2-R3)

- **Issue:** #84 (`P2-R3`)
- **Reviewer:** an independent Claude agent session (the `reviewer` subagent); did not write
  the layer's code
- **Date:** 2026-10-20
- **Commit measured:** `2a48d738d2740b051354495e950041526b466e3a` (`main`, after #486)
- **Verdict:** Not ready

This is the fifth review of the layer. The fourth (commit `bdfebf5`, run
[39409276749](https://github.com/quakecstudio/editor/actions/runs/39409276749)) met every
ratchet and was blocked on P2-74 (#478), macro expansions rendered with a space between every
token. #479, #483 and #486 have closed it and the follow-ups P2-77 (#482) and P2-78 (#484):
the semantic model now renders a token as it touches the one before it (QC-9.16), a builtin or
a label a macro writes reads as the same text written in the file, and qc-sema's README lists
FTE-23.7. #486 also made FTEQW's compiler a porting upstream (ADR-0017) and ported FTEQCC's
macro expansion into `qc-preproc`; the builtins differential grew to 11291 cases.

The Readiness run on `2a48d73` passes every check `cargo xtask ratchet` makes. The layer is not
ready, on one defect this review found by comparing with the pinned FTEQCC:

- **P2-84, functions with no body (`type:feature`).** FTEF-17.7 says "A function with no body
  is an error only where the module refers to it: the bodyless check skips a definition when
  `d->unused && !d->used`". `unused` is the `noref` mark, so FTEQCC reports "function %s has no
  body" for every bodyless function that is not both `noref` and unreferenced: the pinned
  FTEQCC refuses `void() f = #5;` then `void() g;` ("t.qc:2: error: function g has no body"),
  and compiles `noref void() g;`. The FTEQCC profile reports nothing for `g`.

The review added five passing tests.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Claude agent session, about three hours across
  this review and the L2 one. It read #486's changes to qc-sema (`expand::adjacent`) and the
  qc-preproc port that feeds it, built the oracles (`cargo xtask oracles`, macOS arm64), and
  added three batches of cases (130 in all) to the differential's FTEQCC macro family in a
  scratch copy, run with `cargo xtask oracles builtins --record`, then read FTEQCC's
  `qccmain.c` for each difference.
- **P2-74, P2-77 and P2-78, re-checked:** fixed. The differential's macro family binds every
  case of the three issues as FTEQCC does, and of the review's own cases every one whose
  expansion FTEQCC and the profile write alike binds alike, including the five below.
- **Tests added** (five, all passing; each case compiled with the pinned FTEQCC first),
  `crates/qc-sema/src/tests/reviewer.rs`:
  - `reviewer_a_builtin_name_made_by_a_paste_in_an_argument` (FTEF-14.14): `E(x##_a)` written
    inside another macro's body, and `#5:__VA_ARGS__`, bind `ex_a`.
  - `reviewer_a_pasted_macro_name_expands_into_the_builtin` (FTEF-14.14): `Q##x` with `Q` an
    object-like macro writes `Q:ex_a`, which binds builtin 5 named `ex_a`.
  - `reviewer_a_macro_s_own_name_in_its_argument_is_the_engine_name` (FTEF-14.17): `E(E)`
    binds builtin 5 named `E`.
  - `reviewer_a_stringified_built_in_constant_is_its_name` (FTEF-14.15): `:S(__LINE__)` binds
    the name `__LINE__`.
  - `reviewer_a_call_after_the_expansion_ends_binds_nothing` (FTEF-14.18): `E(G)(ex_a)` leaves
    `G` uncalled and `f` unbound.
- **Defects found** (each blocks readiness; issue in `plan/backlog/p2.yaml`, synced to GitHub
  after this PR merges):
  - **P2-84, functions with no body (`type:feature`):** above. FTEQCC's check, in
    `qccmain.c` at the pinned commit: `if (d->unused && !d->used) { continue; }
    QCC_PR_Warning(ERR_NOFUNC, d->filen, d->s_line, "function %s has no body",d->name);`. The
    pinned FTEQCC's results:

    | Input | FTEQCC | FTEQCC profile |
    | --- | --- | --- |
    | `void() f = #5;` then `void() g;` | "function g has no body" | no error |
    | `void() f = #5, g;` | "function g has no body" | no error |
    | `void() f = #5;`, `void() g;` and `void() h = {g();};` | "function g has no body" | `E0211` "function g was not defined" |
    | `void() f = #5;` then `noref void() g;` | compiles | no error |

    It was found through two of the review's macro cases, `#define V(a, ...) a,##__VA_ARGS__`
    with `V(#5, g)` and `#define V(a, ...) a __VA_ARGS__` with `V(#5, :ex_a, b)`.
