# Readiness: P2 L3 semantics (P2-R3)

- **Issue:** #84 (`P2-R3`)
- **Reviewer:** an independent Claude agent session (the `reviewer` subagent); did not write
  the layer's code
- **Date:** 2026-10-19
- **Commit measured:** `368abee8a31940dbdf6b01a32bf9b4a15a4601aa` (`main`, after #446)
- **Verdict:** Not ready

This is the second review of the layer. The first (commit `58c060c`, run
[39303223745](https://github.com/quakecstudio/editor/actions/runs/39303223745)) found it not
ready; #432, #439, #443 and #445 have since landed, and every gap it filed is closed: qc-sema's
branches and mutation are above the bar (P2-43, #437), nested function types lower in linear
time (P2-53, #435), the semantic model has golden corpus indexes, a definitions differential,
properties and a fuzz target (P2-54, #436), and FTEQCC builtin numbers are keyed by value
(P2-56, #440). The Readiness run on `368abee` passes every check `cargo xtask ratchet` makes.

The layer is still not ready, on one defect this review found:

- **P2-67, builtin keys (`type:feature`).** ENGT-4.11 keys an FTEQCC builtin by "the value
  FTEQCC reads from the literal", which FTEQCC binds as `binum = (int)pr_immediate._float;`.
  `fteqcc_value` (`crates/qc-engines/src/check.rs`) parses the shortest decimal Rust prints for
  the `f32` instead, which is another number above 2^24: `#123456789` is keyed 123456790 where
  the `(int)` of its `f32` is 123456792, so `W0311` names a builtin number no compiler binds.
  Under the vanilla dialect ENGT-4.10 reads the literal as a decimal, `#16777217` being 16777217,
  where id's `qcc` binds `f->builtin = (int)pr_immediate._float;`, 16777216. And FTEQCC's
  `#"NAME"` and `:NAME` initialisers, which the parser does not yet accept (P2-66, L2), are to be
  keyed by name.

Everything else meets the bar; the review added five passing tests.

## 5. Independent review (TEST-9)

- **Reviewer and time spent:** an independent Claude agent session, about three hours across
  both P2 re-reviews. It put 70 deep and long constructs, 100000 repeats each, through the
  parser and `Db::module_index` under both profiles in debug and release builds; checked both
  defects of the first review; compared builtin initialisers with the pinned FTEQCC oracle
  (`cargo xtask oracles build`) and with id's `qcc` and FTEQCC's source at their pinned commits;
  and measured the differential's code coverage (section 3).
- **The first review's defects, re-checked:** the exponential lowering (P2-53) is gone:
  `Type::params_of` lowers each parameter once, and `nested_function_types_lower_in_linear_time`
  counts the calls. The deep FTEQCC trees that overflowed qc-sema's stack (P2-50) resolve: none
  of the 70 forms overflowed `Db::module_index` in a debug build at 100000 repeats.
- **Tests added** (five, all passing):
  - `crates/qc-sema/src/tests/reviewer.rs`:
    - `reviewer_deeply_nested_function_types_compare_at_every_level` (QC-10.6): a prototype and
      a body with function types nested 200 deep, every parameter named differently, are one
      function; a body whose innermost parameter is a `vector` is a mismatch.
    - `reviewer_deep_fteqcc_trees_resolve` (QC-27.16): a struct, an initialiser list, a `?:`
      in its middle and an `=` chain, each 100000 deep, resolve with every diagnostic in the file.
    - `reviewer_many_locals_each_resolve_to_their_own` (QC-12.1): 2000 locals in one function,
      each use resolved to its own local, under both profiles.
  - `crates/qc-engines/src/tests.rs`:
    - `reviewer_fteqcc_reads_a_large_number_as_a_float` (ENGT-4.11): `#16777217` is builtin
      16777216 under FTEQCC, as the `float` FTEQCC reads it gives.
    - `reviewer_a_parameter_that_shadows_a_builtin_is_no_builtin` (ENGT-4.2): under FTEQCC a
      parameter named `bprint` shadows the builtin, so only the call of the global warns.
- **Defects found** (each blocks readiness; issues in `plan/backlog/p2.yaml`, synced to GitHub
  after this PR merges):
  - **P2-67, builtin keys (`type:feature`):** above.
  - Found from here against the layer below and filed there (`docs/readiness/p2-r2.md`): a
    10001-line file of chained `#define`s aborts `Db::analyze_module` with a stack overflow in
    the preprocessor (P2-65), and the FTEQCC profile rejects the `#"NAME"` and `:NAME` builtin
    initialisers the pinned FTEQCC compiles with no warning (P2-66).
