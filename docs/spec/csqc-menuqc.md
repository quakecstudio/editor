# CSQC and MenuQC modules

Prefix: `CSM` (registered in [`README.md`](README.md)). IDs follow the rules there: never
renumbered, never reused, withdrawn rather than deleted.

Describes the functions an engine calls in a client-side (CSQC) or menu (MenuQC) module: the
entry points a module defines for the engine to find by name. A project names a module's kind
in its `quakec.toml` (`kind = "csqc"` or `"menuqc"`, PRJ-3.1); this file says which functions of
such a module are the engine's to call, so that the IDE can treat them as used and check their
signatures. System globals and builtin sets are the engine-target database's
([`engine-targets.md`](engine-targets.md)); this file covers the entry points.

The sources are the engines' own declarations, read on 2026-11-16:

- **DarkPlaces**, the engine Xonotic targets: `prvm_offsets.h`, `csprogs.c` and `menu.c` in
  [DarkPlacesEngine/darkplaces](https://github.com/DarkPlacesEngine/darkplaces) at commit
  `6d754e4372fea51fd97689231ecd2ebcbb4c9ad7` (2026-11-05), GPL-2.0-or-later; and the
  declarations it ships for mods, `csprogsdefs.qc` and `menudefs.qc`, as Xonotic carries them in
  `qcsrc/dpdefs/upstream/` (xonotic-data.pk3dir@`7068eb6bb838b97064a4e55646f3df9c3bd633e6`).
- **FTE**, the engine Nuclide targets: `fteextensions.qc`, which FTE writes with its
  `pr_dumpplatform` command ("This file was generated by FTE QW git-6662-247f186a6-dirty, dated
  2024-12-28"), as the Nuclide SDK carries it in `common/fteextensions.qc`
  (VeraVisions/nuclide@`03ea0bdc43471a05032cb1bc35803c146e225df0`).

These are descriptions of what each engine calls; nothing is ported. Implemented by the module
kinds of L-09 (#193). No code implements a statement here yet, so every statement is listed in
[`coverage-baseline.tsv`](coverage-baseline.tsv) until L-09's tests cite it.

## CSM-1 DarkPlaces' CSQC entry points

**Source:** `prvm_offsets.h`, the `PRVM_DECLARE_clientfunction` list; `csprogs.c`, lines 56 to
58; `csprogsdefs.qc`, "prog functions called by engine".

### Behaviour

- **CSM-1.1** DarkPlaces finds these functions of a CSQC module by name
  (`PRVM_DECLARE_clientfunction`): `CSQC_ConsoleCommand`, `CSQC_Ent_Remove`, `CSQC_Ent_Spawn`,
  `CSQC_Ent_Update`, `CSQC_Event`, `CSQC_Event_Sound`, `CSQC_Init`, `CSQC_InputEvent`,
  `CSQC_Parse_CenterPrint`, `CSQC_Parse_Print`, `CSQC_Parse_StuffCmd`, `CSQC_Parse_TempEntity`,
  `CSQC_Shutdown`, `CSQC_UpdateView`, `CSQC_DrawHud`, `CSQC_DrawScores`, `GameCommand` and
  `URI_Get_Callback`.
- **CSM-1.2** `csprogsdefs.qc` declares the signatures of the ones it lists as "prog functions
  called by engine": `void CSQC_Init(float apilevel, string enginename, float engineversion)`,
  `void CSQC_Shutdown()`, `float CSQC_InputEvent(float evtype, float scanx, float chary)`,
  `void CSQC_UpdateView(float vid_width, float vid_height, float notmenu)` ("required for
  EXT_CSQC (preferred)"), `float CSQC_ConsoleCommand(string cmdstr)`, and under `CSQC_SIMPLE`
  ("hud-only CSQC") `void CSQC_DrawHud(vector virtsize, float showscores)` ("required for
  CSQC_SIMPLE (fallback)") and `void CSQC_DrawScores(vector virtsize, float showscores)`.
- **CSM-1.3** A module with `CSQC_UpdateView` draws the whole view, and one without it but with
  `CSQC_DrawHud` is the simple, HUD-only kind: `csprogs.c` checks `if
  (PRVM_ED_FindFunction(prog, "CSQC_UpdateView"))` and then `else if (PRVM_ED_FindFunction(prog,
  "CSQC_DrawHud"))`.

## CSM-2 DarkPlaces' MenuQC entry points

**Source:** `prvm_offsets.h`, the `PRVM_DECLARE_menufunction` list and
`PRVM_DECLARE_function(m_gethostcachecategory)`; `menu.c`, line 5399; `menudefs.qc`, "sys
functions".

### Behaviour

- **CSM-2.1** DarkPlaces finds these functions of a menu module by name
  (`PRVM_DECLARE_menufunction`): `GameCommand`, `URI_Get_Callback`, `m_draw`, `m_init`,
  `m_keydown`, `m_keyup`, `m_newmap`, `m_shutdown` and `m_toggle`.
- **CSM-2.2** `menudefs.qc` declares `void() m_init;`, `void(float keynr, float ascii)
  m_keydown;`, `void(float width, float height) m_draw;`, `void(float mode) m_toggle;` and
  `void() m_shutdown;`, and `// optional: float(float) m_gethostcachecategory;`. `menu.c`
  calls `m_gethostcachecategory` when the module has it (`if
  (PRVM_menufunction(m_gethostcachecategory))`).

## CSM-3 FTE's CSQC entry points

**Source:** `fteextensions.qc`, the `#ifdef CSQC` blocks of engine-called functions, and the
`#if defined(CSQC) || defined(MENU)` and `#if defined(CSQC) || defined(SSQC)` blocks.

### Behaviour

- **CSM-3.1** FTE calls these functions of a CSQC module, declared so in `fteextensions.qc`:
  `CSQC_Init`, `CSQC_WorldLoaded`, `CSQC_Shutdown`, `CSQC_UpdateView`, `CSQC_UpdateViewLoading`,
  `CSQC_DrawHud`, `CSQC_DrawScores`, `CSQC_Parse_StuffCmd`, `CSQC_Parse_CenterPrint`,
  `CSQC_Parse_Damage`, `CSQC_Parse_Print`, `CSQC_Parse_Event`, `CSQC_InputEvent`,
  `CSQC_Input_Frame`, `CSQC_ReloadVideoResources`, `CSQC_GenerateMaterial`,
  `CSQC_ConsoleCommand`, `CSQC_ConsoleLink`, `CSQC_Ent_Spawn`, `CSQC_Ent_Update`,
  `CSQC_Ent_Remove`, `CSQC_Event_Sound`, `CSQC_Parse_TempEntity`, `CSQC_Parse_SetAngles`,
  `CSQC_PlayerInfoChanged`, `CSQC_ServerInfoChanged`, `CSQC_ServerSound` (marked `DEP("use
  CSQC_Event_Sound")`) and `CSQC_MapEntityEdited`; with the menu, `GameCommand`; and with the
  server, `init` and `initents` ("Part of FTE_MULTIPROGS").
- **CSM-3.2** Each takes the signature `fteextensions.qc` gives it, among them
  `void(float apilevel, string enginename, float engineversion) CSQC_Init`, `void(float vwidth,
  float vheight, float notmenu) CSQC_UpdateView`, `float(float evtype, float scanx, float
  chary, float devid) CSQC_InputEvent` (one parameter more than DarkPlaces' CSM-1.2) and
  `void(float isnew) CSQC_Ent_Update`.
- **CSM-3.3** `CSQC_DrawHud` is "Part of simple csqc, called after drawing the 3d view whenever
  CSQC_UpdateView is not defined", as DarkPlaces' CSM-1.3.

## CSM-4 FTE's MenuQC entry points

**Source:** `fteextensions.qc`, the `#ifdef MENU` block.

### Behaviour

- **CSM-4.1** FTE calls these functions of a menu module: `m_init`, `m_shutdown`, `m_draw`,
  `m_drawloading`, `Menu_ReloadVideoResources`, `Menu_InputEvent`, `m_keydown`, `m_keyup`,
  `m_toggle`, `m_consolecommand` and `m_gethostcachecategory`, and `GameCommand` (CSM-3.1).
- **CSM-4.2** `m_draw` is `void(vector screensize) m_draw`, "COMPAT: screensize is not provided
  in DP" (DarkPlaces' takes `float width, float height`, CSM-2.2); `Menu_InputEvent`, "If
  present, this is called instead of m_keydown and m_keyup", which are
  `__deprecated("Use Menu_InputEvent")`.

## CSM-5 The corpus's entry points

**Source:** the CSQC and menu modules of the corpus: Xonotic's `client` and `menu`
(xonotic-data.pk3dir@`7068eb6b`, DarkPlaces) and the Nuclide SDK's `client`, `menu-fn` and
`menu-vgui` (VeraVisions/nuclide@`03ea0bdc`, FTE), each a function the module defines with a
name an engine looks for, or one like it.

### Behaviour

- **CSM-5.1** Every engine-called function Xonotic's modules define is in CSM-1 or CSM-2:
  `CSQC_Init`, `CSQC_Shutdown`, `CSQC_InputEvent`, `CSQC_UpdateView`, `CSQC_ConsoleCommand`,
  `CSQC_Ent_Update`, `CSQC_Ent_Remove`, `CSQC_Parse_TempEntity`, `CSQC_Parse_StuffCmd`,
  `CSQC_Parse_Print`, `CSQC_Parse_CenterPrint`, `m_init`, `m_shutdown`, `m_draw`, `m_keydown`,
  `m_keyup`, `m_toggle` and `m_gethostcachecategory`. Its `CSQC_Demo_Camera` and
  `CSQC_ClientMovement_PlayerMove_Frame` are its own functions, which its code calls
  (`client/view.qc`, `lib/csqcmodel/cl_player.qc`), not the engine's.
- **CSM-5.2** Every engine-called function Nuclide's modules define is in CSM-3 or CSM-4:
  `CSQC_Init`, `CSQC_WorldLoaded`, `CSQC_Shutdown`, `CSQC_UpdateView`, `CSQC_InputEvent`,
  `CSQC_Input_Frame`, `CSQC_Parse_Event`, `CSQC_Parse_Print`, `CSQC_Parse_CenterPrint`,
  `CSQC_ConsoleCommand`, `CSQC_GenerateMaterial`, `CSQC_Ent_Update`, `CSQC_Ent_Remove`,
  `CSQC_PlayerInfoChanged`, `CSQC_ServerInfoChanged`, `m_init`, `m_shutdown`, `m_draw`,
  `m_drawloading`, `m_toggle` and `m_consolecommand`. Its `CSQC_UpdateSeat`, `CSQC_RenderScene`,
  `CSQC_RenderRTEnvSphere`, `CSQC_Update2D`, `CSQC_Parse_Damage_New`, `m_display`, `m_hide` and
  `m_intro_*` are its own functions, which its code calls.
- **CSM-5.3** Nuclide also defines `CSQC_RendererRestarted(string rstr)` (`client/entry.qc`),
  which none of its code calls and which `fteextensions.qc` does not list; FTE's list has
  `CSQC_ReloadVideoResources(string rendererdescription)` for a restarted renderer. The sources
  above are silent on whether FTE calls the older name, so this file does not count it as an
  entry point.
