# ADR-0014: Use FTEQW's and DarkPlaces' extension files as fact-only sources

- **Status:** Superseded by ADR-0015
- **Date:** 2026-10-19
- **Decided by:** Justin Plock
- **Issue:** [#60](https://github.com/quakecstudio/editor/issues/60)
- **Requirements:** LANG-6, PRIN-8, AGT-9, LIC-6, LIC-7

## Question

On what basis may the engine-target database take builtin and extension facts from FTEQW's
`fteextensions.qc` and DarkPlaces' `dpextensions.qc`, which are not porting upstreams?

## Context

LANG-6 asks for an "Engine-target database from fteextensions.qc, dpextensions.qc and
rerelease defs, with diagnostics for unsupported builtins", and P2-04 (#60) says: "Only facts
are extracted (names, numbers, signatures); no comment text is copied; an ADR records the
legal basis." The design document's "Language core" section names the same three files.

`docs/porting.md` lists only id-Software/Quake and the `qcc/` directory of
id-Software/Quake-Tools as porting upstreams. The rerelease QuakeC is already cleared: it is
pinned in `corpus/manifest.toml` as GPL-2.0-or-later. The two engine files were not, so the
implementer escalated #60 with three paths: (A) approve them as fact-only sources now,
(B) ship the cleared engines first and defer the FTE_ and DP_ tables to the P4-22 review, or
(C) make all of P2-04 wait for P4-22 (#133).

No header and no license file forbids taking names, numbers or signatures from these files,
or redistributing such facts. The two engine repositories grant GPL version 2 with no "or
any later version" in their license files, so their text and code are not copied into this
GPL-3.0-or-later project; the corpus policy (`corpus/README.md`) records such a grant as
`-only`, the conservative reading.

## Options

| Option | Consequences |
| --- | --- |
| A. Fact-only sources now (chosen) | P2-04 ships all seven engines' tables. Only facts are extracted, by a script, from files pinned by commit and SHA-256; no comment text or code is copied. Neither engine becomes a porting upstream |
| B. Split the work | P2-04 ships Vanilla, the QuakeSpasm lineage and KEX; the FTE_ and DP_ tables move to a follow-up waiting on P4-22 (#133), and the Ironwail diagnostic of P2-04 rests on a hand-curated FTE_ list |
| C. Defer | P2-04 waits on P4-22 (#133) and leaves Phase 2; LANG-6, PRIN-8 and AGT-9 slip with it |

B and C were not chosen: the facts these files give are what the database needs, and taking
facts alone needs no license to the files' expression, so waiting for P4-22 would delay the
feature without changing what is extracted.

## Decision

Justin Plock decided Path A on 2026-10-19 (#60): FTEQW's `fteextensions.qc` and DarkPlaces'
`dpextensions.qc` are **fact-only sources**. From them, and from the rerelease `defs.qc`, the
engine-target database takes only facts: builtin numbers and engine names, QuakeC names,
signatures and extension names. No comment text and no code of either file is copied into the
repository, and neither file nor its repository is a porting upstream: neither is added to the
upstream table of `docs/porting.md`, and nothing in this repository is ported from them. Each
file is pinned by commit and SHA-256, with its repository's license file, in
`crates/qc-engines/sources.toml`; `cargo xtask engines` fetches the pinned files, checks the
checksums and generates `crates/qc-engines/src/tables.rs`, and the extraction rules are
ENGT-2 in `docs/spec/engine-targets.md`.

This is not legal advice; the license compliance review before the first public release
(P4-22, #133) confirms the details.

## Consequences

- `crates/qc-engines` (L3) holds the tables of Vanilla, QuakeSpasm, Ironwail, vkQuake, FTEQW,
  DarkPlaces and KEX and the missing-builtin warning `W0311` (P2-04, #60).
- A fact source is pinned where its facts are generated, in `crates/qc-engines/sources.toml`,
  not in `docs/porting.md`, whose table lists only the upstreams code is ported from. Taking
  facts from a further file, such as another engine's builtin list, needs the same decision
  for that file.
- CI regenerates the tables from the pinned files and fails on any difference
  (`cargo xtask engines --check`, in the Test Assets (linux) job), so a change upstream never
  enters the tables without a new pin.
- P4-22 (#133) reviews these sources with the rest of the release's license compliance.
