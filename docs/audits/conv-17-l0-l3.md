# Audit: the L0 to L3 crates against CONV-17

- **Issue:** #452 (`P2-60`)
- **Auditor:** a Claude agent session in the role of the dev-agents plugin's `arch-analyst`
- **Date:** 2026-10-20
- **Commit audited:** `2a48d73` (`main`, after #486)
- **Rules:** [`docs/conventions.md`, "Type design (CONV-17)"](../conventions.md#type-design-conv-17),
  and the clean-port policy of [ADR-0017](../adr/0017-port-fteqcc.md) as
  [`docs/porting.md`](../porting.md) states it ("port FTEQCC's behaviour, not its structure";
  "no globals and no transliterated control flow")

Every shipped crate in layers L0 to L3 of `layers.toml` was read in full: 25 crates, test-only
and tooling crates (`qs-tests`, `qs-bench`, `qs-differential`, `xtask`) excluded. Test modules
(`#[cfg(test)]`, `src/tests/`, `tests.rs`, `*_tests.rs`), fixtures, examples and benches were
excluded too; `qc-builtins/src/mock.rs` and `qc-syntax/src/recovery.rs` have no `cfg` gate and
ship, so they were audited. `qc-engines/src/tables.rs` is generated by `cargo xtask engines`
and was audited for its shape only. Nothing clippy already enforces is reported. As extra
evidence, `cargo clippy` with `fn_params_excessive_bools`, `struct_excessive_bools`,
`match_bool` and `too_many_arguments` over the 25 crates reported one warning:
`struct_excessive_bools` on `qc_sema::lower::RawDecl` (qc-sema/2, /7, /9 below).

## How to read it

Each finding has an ID (`<crate>/<n>`), the place (paths are under `crates/` unless they start
with another directory, and lines are at `2a48d73`), the rule, a severity, a confidence and a
disposition.

| Rule | CONV-17 section |
| --- | --- |
| R1 | Enums for closed sets of choices: a `bool` or string standing for a closed set |
| R2 | Newtypes for IDs and units: a `pub` field on an ID or unit, or none at all |
| R3 | Behaviour that reads one type is a method on it |
| R4 | No single-use one-line helpers |
| R5 | Generics and traits instead of duplicated code |
| R6 | No stringly-typed errors in library crates |
| R7 | Transliterated C structure (ADR-0017, porting.md): out-parameters, status codes, parallel arrays, flags carried between loop passes |

- **Severity:** P2 is a public item, a choice threaded through several functions, duplication
  across crates, a `pub`-field ID or a stringly public error; P3 is private or local.
- **Confidence:** high, medium or low that the finding is real and the change is right.
- **Disposition:** the refactoring issue that fixes it (plan keys in `plan/backlog/p2.yaml`),
  or "Accepted" with the reason. A finding about code in one crate whose fix belongs to
  another is listed under the crate that owns the fix.

There is one refactoring issue per layer, P2-139 (L0) to P2-142 (L3), each delivered as one PR
with one commit per crate group, in the order the summary lists them; the four are chained L0
to L3, since each layer adapts to the one below. Each requires that behaviour is unchanged
and every ratchet in `ratchets.toml` (spec citations, coverage, mutation score, fuzz,
differential) is kept.

Two defects that change behaviour were found on the way. They are outside CONV-17, and the
refactoring issues must not fix them, since each requires behaviour to stay the same; they are
filed as their own `type:bug` issues, fixed in commits of their own in the L2 PR (see
[Defects found on the way](#defects-found-on-the-way)).

The most important findings:

- `qc-sema` collapses `Dialect` to a `bool` in two places (qc-sema/1, /5), so the GMQCC
  dialect can never get rules of its own, and reads qualifiers as strings under two different
  spelling rules (qc-sema/2).
- The FTEQCC `__word` spelling rule (FTEF-15.1) is written five different ways across
  `qc-syntax` and `qc-sema` (qc-syntax/2). The copies have already drifted, which causes the
  `enum __class` defect (P2-143).
- Pub-field IDs in four crates: `qc_types` value references (qc-types/1, /2),
  `qc_preproc::{FileId, ExpansionId}` (qc-preproc/12, /13), `qc_sema::{FileId, DefId}`, and
  `ModuleIndex`'s pub vectors (qc-sema/3, /8).
- The VM reports divergences by spec ID as a `&'static str` that it then compares
  (qc-vm/1). `qc-builtins` looks up system globals and fields by name at run time, even though
  `qc-edict/src/system.rs` says the engine never does that (qc-edict/1).
- The little-endian integer reader is copied 12 times across 7 crates, and the copies do not
  agree past the end of the input (cross/1).

- **P2-143: `enum __class X { A };` is a parse error.** `at_enum_body`
  (`crates/qc-syntax/src/parser/fte.rs:556`) accepts `__class` through `fte_word`, but
  `enum_head_and_body` (`crates/qc-syntax/src/parser/mod.rs:763`) tests `at_word("class")`,
  so `__class` becomes the enum's name and `X` fails with E0204 "expected {, found X". By
  reading the code, `__get`, `__set` and `__inline` have the same split between the parser
  (`fte.rs:599-600`, `:684-688`) and `ast::AccessorMember::name` and `is_set`
  (`crates/qc-syntax/src/ast.rs:945-958`). FTEF-15.1 says `QCC_PR_CheckKeyword` "matches any
  keyword written with `__` whether or not it is enabled"; whether FTEQCC accepts these words
  in these places has to be checked in its source.
- **P2-144: a `\` then CR at the end of input reports E0101 twice.** The lexer, given
  `"a\` CR, reports two identical `E0101 "EOF inside quote"` diagnostics with span 0..4:
  `fte_escape` reports one (`crates/qc-lexer/src/fte_string.rs:295`), then `cooked_string`'s
  loop finds the end of input and reports another (`:157-158`).

### Why the test suite missed them

L2's suite is held to fuzzing, coverage and mutation testing (docs/testing.md; the P2-R2
reviews measured each), but none of those checks could see these two defects:

- **Fuzzing** checks that the parser and preprocessor do not crash and that the tree is
  lossless (QA-2). A wrong accept or reject, or a diagnostic reported twice, is neither.
- **Coverage and mutation** measure the code that exists against the tests that exist. P2-143
  is a case with no code at all: `enum_head_and_body` has no `__class` branch. P2-144's second
  E0101 comes from two reports that are each right on their own, and covering both lines does
  not ask how many E0101s one input gets.
- **The differentials** compare the profile with FTEQCC only on the forms someone wrote
  down, such as the builtin-initialiser cross product of `cargo xtask oracles builtins`. No one
  wrote `enum __class`.
- **The root cause of P2-143** is two keyword lists that drifted apart: `fte_word` in the
  lookahead and `at_word` in the parse (qc-syntax/2). A test of either list alone passes.

P2-141 adds two checks aimed at this class of defect, approved by Justin on 2026-10-20, both
in #651:

- a grammar-based FTEQCC differential that compares accept or reject, and the first error's
  message, which names its code, with the pinned FTEQCC on 1000 generated programs
  (`cargo xtask oracles grammar`, DIFF-13); its first runs found seven differences, each fixed
  in a commit of its own with its spec statement;
- a fuzz and property invariant that no code is reported twice at one span (QCD-1.5), which
  catches P2-144 and found three more duplicates in the parser's recovery.
