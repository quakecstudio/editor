# Phase 7 gate: lighting, region compile and performance

Gate issue: [#181](https://github.com/quakecstudio/editor/issues/181) (P7-06). Reviewed on
2026-11-16 at `main` 79edd360 by a reviewer session that did not write Phase 7's code.

**Verdict: met.** The region compile and the background full compile are within their budgets on the reference Mac, as recorded in PRs #937 and #955, and a Benchmarks run this review dispatched on `main` at 79edd360 measured both again on a CI runner, in the same proportion to the reference Mac as the Play from here compile the Phase 6 reviewer measured there. Coloured light agrees with id's `light`
on every corpus map it can light and with ericw-tools' `.lit` on the coloured fixture, in the
Map tool oracles job of the nightly Differential run on `main` at a1b27d33. Every issue in the
phase milestone but this gate is closed, none was deferred without the plan saying so, and no
open PR serves a Phase 7 issue.

### Final coloured lighting (P7-01, #176)

Differential run [43786042894](https://github.com/quakecstudio/editor/actions/runs/43786042894),
scheduled on `main` at a1b27d33 (2026-11-16 01:24 UTC). a1b27d33 is later than every commit that
changes the map compilers (PRs #951, #953, #955, #937); the commits after it, #974 to #982, change
the desktop app and docs only. Its **Map tool oracles** job
([133033794131](https://github.com/quakecstudio/editor/actions/runs/43786042894/job/133033794131))
passed. This review read its log:

- `cargo xtask oracles maps` built id's qbsp, vis and light and ericw-tools.
- `map-diff` printed 34 lines, every one `ok`, none `FAIL`: 0 of 2000 traces differing on hulls
  0, 1 and 2 for every comparison that compiles, as at the Phase 6 gate.
- `light-diff` printed no `FAIL`. Every map id's `light` lights matches it exactly in both modes
  (mean 0.000, largest 0, 0 faces differ): the `room` and `coloured` fixtures, ericw-q1-bmodel-liquid,
  -csg and -cube, lq-e0m1 to lq-e0m8, lq-e1m2, lq-e1m3, lqdm1, lqdm3 and lqdm13. Examples:
  ```
  ok    lq-e1m3 fast light: 219078 compared, mean 0.000, largest 0, 0 past 2, 0 faces differ
  ok    lq-e1m3 extra light: 220593 compared, mean 0.000, largest 0, 0 past 2, 0 faces differ
  ok    coloured fast colour against ericw-tools: 19920 compared, mean 0.010, largest 1, 0 past 2, 0 faces differ
  ```
- Both stop, alike: lq-start (`the pair of key _comment is too long for id's light`, id's light
  aborts) and lqdm5 (`LoadEntities: MAX_MAP_ENTITIES`, id's light faults).
- Skipped, with the reason printed: lq-e1m1 (4240 texinfo past `MAX_MAP_TEXINFO`, 4096), lq-e2m5,
  lq-e3m4 and lq-e4m5 (models past `MAX_MAP_MODELS`, 256), which id's `light` copies into with no
  bound check; lq-end, pd-elevator, pd-lava and ericw-q1-clip-func-wall, which id's qbsp does not
  compile; and the colour comparison on 13 maps that use ericw-tools' own lighting keys (`_sun`,
  `_surface`, `_bounce`, `_dirt`, `_phong` and the like), which is post-MVP work under
  [ADR-0027](../adr/0027-advanced-lighting.md) (#979, #980).
- **The `.lit` loads in the preview host:** `qs-tests::it play_from_here::a_coloured_light_lights_the_preview_in_colour`
  passed in PR #974's Unit Tests (linux) job
  ([133060927934](https://github.com/quakecstudio/editor/actions/runs/43794719339/job/133060927934)),
  as did `qs-map-light tests::coloured_light_writes_a_lit_file`.

### Region compile (P7-03, #178)

- **Within budget:** PR #937 recorded `region_compile_e1m1` at 182 ms (177.8 to 187.4 ms)
  on the reference Mac against a 1.2 s budget. In the Benchmarks run below it took 352.52 ms
  median (p95 367.67 ms) on the CI runner, under the budget even there.
- **At least 5x faster than a full fast compile** (P7-03's criterion): PR #937 recorded 182 ms
  for the room against 3.47 s for the whole map on the reference Mac (Apple M5), 19 times faster.
  The Benchmarks run at 79edd360 confirms it on one machine at one commit: one room in
  352.52 ms against 10.400 s for the whole map (`play_from_here_e1m1`), 29 times faster.
- **Behaviour**, in PR #974's Unit Tests (linux) job above, all passing: `qs-map region::tests`
  (a region is a box with volume, the cut keeps what is in it and the player start inside, sealed
  on six sides; MAP-16.1 to 16.3) and `qs-workbench map_compile::tests`
  (`a_region_around_an_open_room_does_not_leak`, `a_layer_compiles_as_its_region`,
  `a_region_with_no_volume_is_refused`, `play_from_outside_the_region_is_refused`).

### Background full compile (P7-02, #177, and P7-07, #182)

- **Within budget:** PR #955 recorded `full_compile_e1m1` at 6.16 s median on the reference Mac
  (BSP 3.1 s, vis 2.3 s, light 0.7 s) against an 8 s budget. The Benchmarks run below measured
  20.128 s on the CI runner (below, for why that is not the budget's number). Since #955 the
  map compilers changed only by QBSP-15.53's animated texture frames (#970), which adds no work
  to a map without `+` textures beyond a check of each texture name's first byte.
- **Swapped in, keeping the game's state:** PR #974's Test Assets (linux) job
  ([133060927887](https://github.com/quakecstudio/editor/actions/runs/43794719339/job/133060927887))
  ran `cargo xtask bridge-client` on LibreQuake against the real preview host:
  `ok    map/swap of the map's own BSP keeps the player and every entity`, `bridge-client: 18
  steps passed`. The Unit Tests (linux) job passed `qs-workbench preview::live_tests`
  (`a_full_build_is_swapped_into_the_running_game`, `a_stale_full_build_is_dropped`,
  `a_full_build_asked_for_while_one_runs_replaces_it`), `qs-workbench full_build::tests`
  (`a_full_build_sees_and_lights_the_map`), the `qs-sim world::swap::tests` (a renamed door takes
  its model, a trigger keeps showing nothing, a hidden door takes its new name, the world collides
  in the new BSP) and `quakec-engine game::tests::a_swap_that_cannot_be_made_is_refused`.
- The Unit Tests (linux) job ran 6300 tests: 6300 passed, 3 skipped.

### The rest of the budgets

Benchmarks run [43798550066](https://github.com/quakecstudio/editor/actions/runs/43798550066),
dispatched by this review on `main` at 79edd360 (2026-11-16 03:30 UTC), passed. Its history
(`cargo xtask bench history`, host `ci-Linux-X64`), for the map rows:

```
play_from_here_e1m1      active  median   10.400 s  p95   10.586 s  p99   10.586 s
region_compile_e1m1      active  median  352.52 ms  p95  367.67 ms  p99  367.67 ms
full_compile_e1m1        active  median   20.128 s  p95   20.240 s  p99   20.240 s
textured_view_e1m1       active  median   33.72 ms  p95   40.45 ms  p99   40.45 ms
```

This was the first run of `region_compile_e1m1`, `full_compile_e1m1` and `textured_view_e1m1` on
a CI runner (the previous Benchmarks run on `main` was on 2026-11-09). A CI runner is judged by
the regression rule only, never by the budgets (`xtask/src/bench.rs`, `Machine::Other`, decided
by Justin on 2026-11-04 for P2-166), so these are not the budgets' numbers. They are used here
as an independent cross-check of the recorded reference Mac numbers: the Phase 6 gate reviewer,
who did not write the code, measured `play_from_here_e1m1` on the reference Mac at 3.3545 s; the
runner took 10.400 s, 3.1 times as long. In that proportion the runner's 20.128 s for the full
compile is about 6.5 s on the reference Mac, within 8 s, and its 352.52 ms for the region about
114 ms, within 1.2 s. The textured view's 33.72 ms is within its 50 ms budget on the runner
itself; the reference Mac recorded 10.4 ms (`docs/perf-budgets.md`). Play from here's 10.400 s is over
its 6 s budget on the runner, where no budget is judged; on the reference Mac it is the
3.3545 s above.

This review did not run the benchmarks on the reference Mac: it was in use for other work, and
a benchmark on a loaded machine would not measure the budget.
