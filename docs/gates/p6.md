# Phase 6 gate: brushes and map compiler

Gate issue: [#171](https://github.com/quakecstudio/editor/issues/171) (P6-14). Reviewed 2026-11-14 against `main` at c702f4c, by a reviewer session that did not write Phase 6's code, at Justin's request of 2026-11-14. **Verdict: not met.** A new map built from brushes compiles with our three tools and plays, in CI and in this review's own run with LibreQuake's QuakeC. But the map differential's first run on `main` is red, the preview host panics drawing a new map that has no WAD, Play from here is over its 10 s budget on `main`, and the MCP server lacks the map tools that a closed issue's deliverable names. All four can be fixed in this phase. They are filed in the plan as P6-35 to P6-38, and each one is a dependency of the gate. The gate stays open.

### Closed issues whose criteria do not hold on `main`

- **P6-12 (#169), "Under 10 s from click to playing on an id1-sized map"**: PR #909 recorded lq-e1m1 "compiled in 1.05 s, 1.38 s with the light". PR #914 then replaced the extended dialect, which every workbench compile uses (`crates/qs-workbench/src/map_compile.rs:121`). This review timed the same compile (qs-map-bsp extended, then fast light), release builds, on one Apple M5:

  | Map | 80a0503 (#909) | c702f4c (`main`) |
  | --- | --- | --- |
  | lq-e1m1 | 1.11 s, 1.45 s with the light | 12.40 s, 12.64 s with the light |
  | lq-e3m4 | 4.12 s, 4.25 s | 15.75 s, 16.02 s |
  | lq-e1m2 | 0.32 s, 0.38 s | 4.55 s, 4.60 s |

  On `main`, lq-e1m1 is over the 10 s budget before the host starts. No check measures this compile, so the regression went unseen: P6-37.
- **P6-21 (#822)**: the deliverable says the brush, shape and CSG commands are "offered to the agent and MCP so they build level geometry", and PR #913 says so too. The built-in agent has them. `quakec-ide mcp` does not: `tools/list` answers 26 tools, the `qs_mcp::AGENT_TOOLS` list (`crates/qs-mcp/src/lib.rs:65`), and none of them is `map.*`. `docs/mcp.md`'s tool table has none either: P6-36.
- **P6-20 (#821), "A profile running qs-map-bsp, qs-map-vis and qs-map-light then launching the preview host works on each OS"**: the test asserts that `launch` fails, since CI has no game. No run starts the host on a profile's output. This review's host run above is that missing step, and P6-35's acceptance covers it.

### Other observations

- **The corpus plays.** Every corpus map compiled with qs-map-bsp in the extended dialect, in 0.45 ms (`ericw-q1-cube`) to 35.9 s (`lq-e2m5`). `cargo xtask scenario` (20 frames, `expect field player classname == "player"`) over LibreQuake lite passes on 22 of 26. `ericw-q1-csg` has no `info_player_start` (`PutClientInServer: no info_player_start on level`). lq-e2m5, lq-e3m4 and lq-e4m5 stop on `PF_precache_model: overflow`, the 256-model limit (LIMIT-6.2) that P6-04's PR #896 already recorded for 25 LibreQuake levels.
- **The map differential compares qbsp only.** Vis and light are checked by their own tests (P6-05's conservative PVS, P6-06's time), not against id's or ericw-tools' vis and light. PR #914 removed "rendered views" from P6-07's deliverable, by a plan change.
- **Mutation on the extended dialect.** PR #914 recorded 73% on its diff (`src/extended/`, 421 missed) and said "L4's readiness review holds the crate to the 90% bar". No such review exists: from Phase 3 on a phase has its gate review alone, and the P6 readiness issues #172 to #175 and #211 are closed as not planned.
